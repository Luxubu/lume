## Guesses

1. **Structural conformance across packages.** `catalog.Book` (c01) and `players.Player` (c04) are used where `pricing.Priced` / `ranking.Scored` is bound, though their packages do not depend on the interface's package. Looked in interfaces.md ("there is nothing to declare"), generics.md "Interfaces as bounds", packages.md (the orphan rule only speaks of `extend`). Nothing says where the conformance is worked out when the type's package cannot see the interface. Assumed it works, since the whole program is one Rust crate (packages.md, Rust crates).
2. **Calling an interface default on a foreign type outside any bound.** `b.tag` on a `catalog.Book` (c01), `team.at(1).grade` on a `players.Player` (c04), from a file that imports the interface's package. interfaces.md says defaults become "the type's own methods afterwards", but every example has the type and interface in one file. Assumed it works whenever the interface's package is imported.
3. **How a struct from another package prints.** `Some(Money(cents: 2000))`, `Rule(name: "lower", check: <block>)`, `[Coin(face: 9)]`. printing.md and structs-and-enums.md only print types of the same file. For enums, "it still prints as the bare variant name" is stated; for struct type names across modules or packages it is not. Assumed the bare type name, without `units.`.
4. **A generic type from a package, with type arguments, in an annotation.** `pricing.Basket[catalog.Book]` (c01), `[pipeline.Stage[Int]]` (c03). modules.md shows `[items.Item]` and `st.Stock`; generics.md shows `Stack[Str]`; the two never appear together. Assumed `prefix.Type[Args]`.
5. **A bound spelled with a package prefix.** `[T: pricing.Priced]` (c01), `[T: ranking.Scored]` (c04). modules.md shows an interface through a prefix as a type (`[items.Priced]`) and imported by name; generics.md shows bounds only on same-file interfaces. Assumed the prefixed form is a valid bound.
6. **Importing a module from a subfolder of a dependency.** `import core.model.event` (c02, for `core/model/event.lume`, which `core/lib.lume` passes on with `pub import model.event`), and `import html.format.text as ht` (c06). packages.md shows only `import tally.counts`, for a module at the package root. Assumed the path after the package name is the module's path inside the package, and that `as` works on it as on a module.
7. **Whether passing on works through a package import, and whether your own import still wins.** In c06 `html/lib.lume` has `pub import format.text`; the app has its own `text.lume` and writes `import text`. modules.md says the importer's own import wins over a passed-on name. packages.md never says whether `import html` brings `text` in bare at all (shelf writes `import tally.counts` anyway). Assumed modules.md's rules hold for packages. Either way the output is the same. I also left md's `text` private rather than risk "passed on by two modules".
8. **A library constant computed from another package's constants.** `pub SPAN = limits.MAX_LEN - limits.MIN_LEN` (c03). modules.md says a constant may use "arithmetic on other constants" and "constants written above it"; imported ones are not mentioned. Assumed allowed.
9. **A generic struct with a kept block of its own parameter.** `pub struct Stage[T]: run: (T) -> T` (c03). functions-and-blocks.md shows kept blocks in non-generic structs, and generic structs taking block *parameters*, but never a block *field* typed with `T`. Assumed it works, with `T` read from the annotation on the list.
10. **`spawn:` inside a library `async def`.** `net.quote_all` spawns one task per name and awaits the list (c05). concurrency.md says "`spawn:` needs `async def main`", meaning the program's; every example spawns in `main`. Assumed a `spawn:` in any `async def` is fine when the program's `main` is async.
11. **An `extend` target with a package prefix.** `extend coins.Coin with Scored` in `ranking` (c04). packages.md shows the prefix only on the interface (`extend Label with tally.Sized`) and states that the interface's package may extend a foreign type, but never spells that. Assumed the prefix works in the target.
12. **`[Int or Error]` as a type.** This is the return type of `net.quote_all` (c05). Docs write `Task[[Pair] or Error]` and `Task[T or Error]`, but never a list whose items are results. Assumed `[T or Error]` means a list of results.

## Verdict

Twelve guesses across seven programs. The package pages answer the "can I reach it" questions well: `pub`, `pub import`, private modules with the same name, dependencies of dependencies, the orphan rule, and paths from the package root. Most of my guesses are about **spelling where two documented features meet across a package boundary**: a prefix on a bound, on a generic type with arguments, on an `extend` target, and on a module in a subfolder. The other kind is about **behaviour that is only shown inside one file**: structural conformance and interface defaults when the type's package cannot see the interface, and how a foreign struct prints. Three more docs would remove about half the list. One is a packages.md example that imports a subfolder module of a dependency. Another is a line saying conformance is structural across packages too, with the defaults following. The last is a printing line for types from other modules.
